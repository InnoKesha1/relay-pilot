# Проверки Relay Pilot — 6 сентября 2026

Статус: локальный прототип с автоматическими проверками; выпуск пользователям ещё не подтверждён. Проверки выполнены на Windows в рабочем окружении разработчика. CI в GitHub не запускался.

Стенд использует разные loopback-адреса и смешанный SOCKS-вход вместо системного TUN. Он не меняет VPN или маршрутизацию компьютера. Контрольный HTTPS/DNS-сервер принадлежит тесту. Пробы автоматического выбора на стенде используют локальный HTTP; профиль для развёртывания использует HTTPS.

## Открытые проверки и ограничения

- APK и установщик Windows ещё не собраны и не установлены. На этом компьютере Flutter-сборке плагинов мешает отключённая поддержка symlink/Developer Mode. Actions подготовлен для позднейшего запуска; постоянный Android signing key ещё не задан.
- Нет реального Linux-прогона systemd, SSH, правил межсерверного доступа, получения/продления сертификатов и восстановления после перезагрузки. Нет купленных VPS, домена и инвентаря владельца.
- Требуется проверить raw-запуск встроенного Hiddify Core 4.1.0 с системным TUN на обеих платформах, защищённый RPC на Android, импорт камерой, обновление APK/Windows поверх прежней версии, отсутствие прямого DNS в захвате трафика устройства.
- Остановка входа B проверена; блокировка всего UDP реальным firewall/оператором ещё не проверена. Переключение сети, сон/пробуждение, длительное соединение и пять отдельных устройств не проверены.
- Наблюдаемые задержки — результат одного итогового локального прогона, не гарантия для любой сети. Период проверки 15 с не гарантирует восстановление за 60 с при любых потерях и тайм-аутах; это порог приёмки на целевых сетях.
- Защита от прямого доступа действует в конфигурации активного туннеля. Системный режим «блокировать без VPN», остановка самого приложения/ядра и восстановление системных маршрутов требуют отдельной проверки и настройки ОС.
- Мониторинг проверяет синхронизацию конфигураций и работоспособность процессов; внешние end-to-end пробы, доставка уведомлений и хранение за пределами VPS ещё не подключены. История посещений не собирается.

## Приёмка перед выдачей доступа

1. Прогнать полный стенд на Linux из workflow, включая регрессионные проверки коротких ответов со smux.
2. Собрать через Actions, установить и обновить APK/Windows, импортировать ссылку и QR. Проверить подключение, маршруты и задержку.
3. На реальных трёх VPS подтвердить два хопа и DNS через выход захватом трафика и собственным IP-эхо ресурсом.
4. Отключить по очереди входы, перекрыть UDP, затем общий выход. Измерять восстановление новых соединений, порог — 60 с при живой альтернативе.
5. Проверить неверное обновление, срок, отзыв уже активного пользователя, задержанную синхронизацию, 75-секундный предел остановки узла при потере управления, восстановление базы без возвращения отозванных пользователей.
6. Смена Wi-Fi/мобильной сети, сон/пробуждение, пять одновременных устройств; сначала владелец, затем до десяти участников.
